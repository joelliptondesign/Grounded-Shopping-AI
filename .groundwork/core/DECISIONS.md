# Decision criteria

Record choices that establish durable behavior, resolve conflicting guidance, change important authority/architecture/evaluation boundaries, or make a consequential tradeoff future work needs to understand. Judge meaning, not line count.

Routine edits and restoring an agreed requirement need no new record. Link an existing record when it covers the choice. Update evidence and follow-up while preserving accepted rationale; use a successor for a material reversal. Proposed records do not authorize implementation.

At the existing checkpoint, use none, existing, update or create. Explain the disposition and link relevant records. It is relative to the selected Git base, not the last chat turn. Mixed work uses the most expansive applicable disposition. The receipt documents assessment; the record retains the actual decision source and rationale.

Optional generated guidance selects the active record explicitly through the project map. Structured metadata owns its concise rule and rationale. Full authored rationale, alternatives, approval history and evidence stay in the record. A selected source must be accepted and nonsuperseded; a tool does not authenticate those declarations. Preserve unselected historical records.
